# Реанимация клиентов

Список, Excel, фильтры, сортировка, карточки и формы звонков используют общие расчёты.
Срок ограничивает только неактивность по orders_stats.saved_at. Клиенты без статистики тоже входят в список.
Показатели считаются за всё время: заказы/марки/строки из orders_stats, пополнения и промокоды — из успешных
user_transactions соответствующего типа, списания — из успешных order_payment/users_order_payment
с баланса клиента. Возвраты не вычитаются, транзакция учитывается один раз. Средний чек — списания / число заказов.
Перед Excel таблица обновляется теми же фильтрами. Канала регистрации в этом проекте нет: он не добавлялся.

Каркас и таблица загружаются отдельно; сортировка по логину сохраняется при пагинации.
Логин копируется с уведомлением, рядом — иконка заказов. Форма звонка перед логином, без изменения прав доступа.
Сервер разрешает только недозвон/перезвон/успех либо пустую строку для сброса, иначе возвращает 400 без записи.
Время последнего сохранения: dd.mm.yyyy HH:MM. История звонков и автор изменений не сохраняются.
Статус Excel, управление активацией и запрос ссылки для нового пароля из таблицы убраны.

Проверка: python -m unittest discover -s tests -p test_reanimate.py -v
SQL-тесты создают отдельный временный PostgreSQL в /tmp и не используют БД приложения.
Миграции не требуются. Telegram-уведомления в этот проект не переносились.

Переключатель «Включать клиентов, которые ещё не заказывали» по умолчанию включён.
При выключении исключаются клиенты без записей orders_stats за всё время. Значение
сохраняется при сортировке, пагинации и в Excel, где также указывается в фильтрах отчёта.
Блок фильтров ограничен шириной 760px, широкая таблица прокручивается отдельно.
