# Обновление NGINX: 20.11.2026

Охват: контейнер `nginx` на `82.97.252.99` (`/root/Markineris-2.0`)
и `109.68.214.71` (`/root/Markineris2.0.r`), Compose project `elastic`, ветка `main`.
На обоих серверах до обновления: официальный образ `nginx:1.25.2`, пакет
`1.25.2-1~bookworm`, OpenSSL runtime 3.0.11. Это пакет upstream NGINX,
а не системный пакет Debian с независимым циклом backport-исправлений.

Источники:
- [Официальный бюллетень](https://nginx.org/en/security_advisories.html)
- [Изменения mainline](https://nginx.org/en/CHANGES)
- [Каталог официальных образов](https://github.com/docker-library/official-images/blob/master/library/nginx)

## Выбранный образ

`nginx:1.31.9@sha256:5b9ebb95001cc4f5242fbc3e1a9ac76d313c8ba197c7e5803a77d3f7879f0cda`

Это официальный manifest **linux/amd64**, проверенный через Docker Hub и
локальный запуск: NGINX 1.31.9, OpenSSL 3.5.7. При переносе на другую
архитектуру нужно выбрать и проверить соответствующий manifest.
Сохранены mainline и семейство Debian; новый официальный образ основан на
Debian trixie. Все десять CVE закрыты этой версией согласно бюллетеню.
Не добавляются сторонние репозитории. Существующие конфигурация, TLS-политика,
сертификаты, порты, сети и upstream остаются прежними.

Локально выполнены `nginx -t` новым образом для обоих проектов с временным
тестовым сертификатом и подстановкой имён upstream через `/etc/hosts`;
проверены Compose-файлы и закреплённый образ. Это проверка синтаксиса;
реальные сертификаты и DNS проверяются отдельно на проде до переключения.

## Применение после локального commit и push в main обоих проектов

На каждом сервере отдельно:

1. Сверить branch, HEAD, tracked diff, Compose labels и архитектуру.
   Сохранить root-only резервную копию Compose, каталога nginx с ключами,
   `nginx -T`, inspect контейнера и старого image ID вне Git.
2. Снять исходные HTTP/HTTPS статусы и redirects для всех server_name,
   health, статического ресурса, API и дополнительных портов.
3. Выполнить `git pull --ff-only origin main`, сверить ожидаемый commit.
4. `docker compose -p elastic -f docker-compose.yml config --quiet`
5. `docker compose -p elastic -f docker-compose.yml pull nginx`
6. Проверить новый image `nginx -V` и `nginx -t` с реальными mounts,
   read-only копией конфигурации и подключением ко всем действующим сетям.
7. `docker compose -p elastic -f docker-compose.yml up -d --no-deps --force-recreate nginx`
8. Проверить новый container/image ID, `nginx -v`, `nginx -t`, конфигурацию,
   HTTP/HTTPS с проверкой доверия сертификатам, HTTP/2, API, reverse proxy,
   статику и логи. Сравнить с исходными ответами. Проверить все работающие
   контейнеры, чтобы не осталось старого NGINX на этих двух серверах.

Это замена готового официального образа; собственной сборки NGINX нет.
Перезапуск одного контейнера может кратковременно прервать соединения.
`docker compose down` и перезапуск приложения/БД не требуются.

При сбое после переключения использовать сохранённый старый image ID через
временный Compose override только для сервиса nginx и повторить проверки.
Такой откат возвращает уязвимый бинарник и является аварийной мерой;
root-only backup и старый image не удалять до завершения проверки.
