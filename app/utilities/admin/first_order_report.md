# Отчёт первичного заказа

Страница `/admin_control/first_order_report/` доступна активному `superuser` из колонки «Управление пользователями» в панели администратора (в этом проекте колонка называется «Управление клиентами»). Выгрузка Excel доступна по `/admin_control/first_order_report/excel` с теми же правами.

Отбираются пользователи с ролью `ordinary_user`, у которых самый первый отправленный в работу заказ за всю сохранённую историю попадает в выбранный период. Дата регистрации не ограничивается периодом. Черновики не учитываются.

Источником заказов служит `orders_stats`, как в общей статистике заказов: запись создаётся при отправке заказа в работу и сохраняется в истории. Дата заказа — `crm_created_at`, а для старых записей без неё — `created_at`. Поэтому начало заполнения черновика в октябре и отправка в ноябре относятся к ноябрю. Статусы заказа дополнительно не фильтруются.

Сначала по всей истории определяется минимальная дата заказа каждого пользователя, затем применяется период. Количество заказов пользователя считается внутри того же периода. Поля фильтра используют формат `ДД.ММ.ГГГГ ЧЧ:ММ`, календарь с выбором месяца/года и отдельным вводом времени. Конечная минута включается целиком, включая секунды. По умолчанию выбран период с первого числа текущего месяца 00:00 до сегодняшнего дня 23:59. Старые ссылки с ISO-датами без времени работают как раньше и включают обе даты целиком.

В этом проекте отсутствуют анкета регистрации и таблица `user_registration_surveys`, поэтому в колонке источника привлечения выводится «Не указан». SQL отчёта не обращается к отсутствующей таблице; для начала сбора источников потребуется отдельное изменение модели и схемы БД. Миграции в рамках переноса не создаются. Агент — текущий `users.admin_parent_id`, отображается его `login_name` с запасным вариантом email; при отсутствии — «Без агента». Исторический агент на дату первого заказа отдельно не восстанавливается.

Колонка «Текущий баланс, ₽» рядом с пользователем показывает текущее значение `users.balance` на момент формирования отчёта, включая отрицательный баланс. Это не исторический баланс на конец выбранного периода. В Excel баланс также записывается числом с денежным форматом.

В таблице можно сортировать по дате регистрации и первого заказа в обе стороны. Сортировка применяется до серверной пагинации; для одинаковых дат порядок фиксируется ID пользователя. Фильтры, сортировка и страницы обновляют таблицу через `fetch` с эффектом fade. Старый запрос отменяется при запуске нового.

Пагинация оформлена как в экосборе: номера по центру, переходы к первой и последней страницам, многоточия и счётчик показанных строк. При одной странице номера скрыты. Колонка «№» содержит сквозной порядковый номер в выбранном порядке сортировки, включая предыдущие страницы. В Excel первый столбец также содержит порядковый номер, а не ID пользователя.

Под фильтром дат находятся 12 кнопок месяцев текущего года, в одну или две строки в зависимости от ширины экрана. Кнопка подставляет начало месяца 00:00 и конец месяца 23:59; для текущего месяца конец ограничен сегодняшним днём. Будущие месяцы недоступны. После подстановки диапазона отчёт формируется кнопкой «Показать»; ручной ввод дат также доступен.

Excel содержит весь отфильтрованный набор в выбранном порядке, независимо от текущей страницы, с обеими датами и агентом. Имя файла включает «Отчёт первичного заказа» и даты периода. Даты записываются как даты Excel, пользовательские текстовые значения — как текст.

Схема БД не изменяется; миграции не требуются.
